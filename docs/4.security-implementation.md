
# 🔐 Security Implementation

## Overview

Security was designed using layered protection across networking, access management, and monitoring.

---

## 1. Network Security

### Public Access Limited to Load Balancer

* Only the Application Load Balancer is exposed to the internet.
* Public traffic is received on HTTP/HTTPS ports.

### Private Application Servers

* EC2 instances are deployed in private subnets.
* No direct public IP access is provided.

### Private Database Layer

* Amazon RDS is deployed in private database subnets.
* Database is not publicly accessible.

---

## 2. Security Groups

### ALB Security Group

Allowed Inbound:

* Port 80 (HTTP) from internet
* Port 443 (HTTPS) if SSL enabled

Allowed Outbound:

* Application server traffic

### Application Security Group

Allowed Inbound:

* Port 80 from ALB Security Group only

Allowed Outbound:

* Database traffic to RDS
* Internet access through NAT Gateway (updates/packages)

### RDS Security Group

Allowed Inbound:

* MySQL (3306) or PostgreSQL (5432)
* Source: Application Security Group only

---

## 3. Identity and Access Management

* IAM Role attached to EC2 instances
* Used for Systems Manager and CloudWatch access
* No hardcoded AWS credentials stored on servers

---

## 4. Administrative Access

### AWS Systems Manager Session Manager

* Used for secure shell access
* No SSH keys required
* No port 22 open to internet

---

## 5. Monitoring & Alerts

Amazon CloudWatch configured for:

* CPU spikes
* Unhealthy targets
* Resource visibility

---

## 6. Best Practices Followed

* Least privilege access
* Private subnet deployment
* Managed database service
* Role-based authentication
* Reduced attack surface
* Centralized monitoring

---

## Security Outcome

This environment follows production-style AWS security principles with segmented access and minimized public exposure.
