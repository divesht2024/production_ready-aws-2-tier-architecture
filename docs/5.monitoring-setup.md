
# 📊 Monitoring Setup

Monitoring for the infrastructure was implemented using **Amazon CloudWatch** to track performance, health, and resource usage across compute, load balancing, and database layers.

---

## 1. EC2 Monitoring

Enabled monitoring for application servers running in the Auto Scaling Group.

### Metrics Tracked

* CPU Utilization
* Network In
* Network Out
* Status Check Failed
* Disk Activity (basic metrics)

### Purpose

* Detect high CPU usage
* Observe traffic trends
* Verify instance health

---

## 2. Application Load Balancer Monitoring

CloudWatch metrics used for ALB health and traffic analysis.

### Metrics Tracked

* Request Count
* Target Response Time
* Healthy Host Count
* Unhealthy Host Count
* HTTP 4xx / 5xx errors

### Purpose

* Confirm traffic is reaching the application
* Detect unhealthy backend instances
* Analyze response performance

---

## 3. Dashboard Setup

Created a centralized CloudWatch dashboard showing:

* EC2 CPU graphs
* ALB request metrics
* Healthy host count

---

## 4. Operational Benefits

* Real-time visibility
* Faster troubleshooting
* Performance analysis
* Production readiness

---

## Conclusion

CloudWatch monitoring adds observability to the architecture and helps maintain availability, performance, and reliability.
