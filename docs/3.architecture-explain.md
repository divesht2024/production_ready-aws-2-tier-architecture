
# 🏗️ Architecture Explanation

## Overview

This project follows a **2-tier AWS architecture** designed for security, scalability, and high availability.

The architecture separates the application layer and database layer into different tiers.

---

## Tier 1: Application Layer

* Users access the application through an **Application Load Balancer (ALB)**.
* The ALB receives incoming traffic from the internet.
* Traffic is distributed across multiple EC2 instances.
* EC2 instances are deployed in **private subnets** across multiple Availability Zones.
* Auto Scaling Group automatically maintains the desired number of instances.

---

## Tier 2: Database Layer

* Amazon RDS is used as the managed relational database.
* The database runs in **private database subnets**.
* It is not publicly accessible.
* Only application servers are allowed to connect.

---

## Networking Design

* Public subnets host the ALB and NAT Gateway.
* Private subnets host EC2 application servers.
* Separate private DB subnets host Amazon RDS.
* Route tables control traffic flow between resources.

---

## High Availability

* Resources are deployed across multiple Availability Zones.
* Load Balancer routes traffic only to healthy targets.
* Auto Scaling can replace unhealthy EC2 instances.
* RDS can be configured for Multi-AZ failover.

---

## Security Design

* Only ALB is exposed publicly.
* Application servers have no public IP addresses.
* Database is private.
* Security groups restrict communication between layers.

---

## Monitoring

Amazon CloudWatch is used for:

* EC2 CPU and network monitoring
* ALB health metrics
* RDS performance metrics
* Alerts and dashboards
